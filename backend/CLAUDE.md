# Бэкенд портала — записки для агента

Запуск и переменные окружения — в корневом `CLAUDE.md`.

Фреймворка здесь нет намеренно: голый `node:http`, свой роутер на регулярках
(`router.js`), `pg` без ORM. Пока API умещается в пару десятков ручек, слой
абстракции стоил бы дороже, чем экономил.

## Чем этот код опасен

**Слушатель запроса выполняется синхронно, и любой брошенный оттуда объект
роняет процесс.** Не отдаёт 500 — роняет весь сайт. Так уже случалось трижды:

- `decodeURIComponent` кидает `URIError` на одиноком проценте — хватало `GET /%`.
  Отсюда `safeDecode` в `server.js` и try/catch в `util/cookies.js`.
- `a2s.js` читал байт по фиксированному смещению из UDP-датаграммы, которую
  присылает кто угодно. Короткий пакет — исключение. Длину проверять **до**
  любого `read*`.
- Промис без `.catch()` в обработчике: отброшенное отклонение в новых Node
  завершает процесс. У каждой ручки, возвращающей промис, должен быть хвост,
  отвечающий клиенту и ловящий ошибку.

Правило простое: всё, что приходит снаружи — URL, кука, тело, UDP-ответ —
считается враждебным, и разбор каждого обёрнут.

**Роль берётся из базы, а не из токена.** JWT игрок носит с собой; понижение в
правах не должно ждать, пока протухнет токен. `patchUserRole` уже читает ранг
актора через `findUserById` — новые проверки прав делать так же.
(`requireRole` всё ещё смотрит в токен — это незакрытый хвост, см. корневой файл.)

**Всё, что пришло от пользователя и попадает в HTML, проходит через
`escapeHtml` из `frontend/common.js`.** Имена серверов и ников приходят из базы
и из A2S-ответов чужих серверов — ни то, ни другое не наше.

## Проверка

Postgres должен быть поднят, иначе `/api/health` вернёт 500 — это не поломка кода.

```bash
curl -s http://127.0.0.1:3001/api/health     # {"status":"ok","db":"ok"}
curl -s http://127.0.0.1:3001/api/servers
```

Проверять устойчивость надо живым запросом, а не рассуждением: битый URL,
огромное тело, оборванное соединение. Каждый из трёх пунктов выше выглядел
безопасным на чтение.
