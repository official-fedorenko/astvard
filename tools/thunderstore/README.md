# Пакет для Thunderstore

Отсюда собирается архив, который заливается на
[thunderstore.io](https://thunderstore.io/c/valheim/). Игрок ставит его одним
кликом через Thunderstore Mod Manager или r2modman, а BepInEx и Jötunn менеджер
подтягивает сам — они объявлены зависимостями и не ставятся повторно, если уже
есть.

## Собрать

```bash
dotnet build valheim-mod/AstvardServerMod/AstvardServerMod.csproj -c Release
python tools/thunderstore/build.py
```

Рядом появится `AstvardServerMod-<версия>.zip`. Публикация — руками на сайте,
под своей командой: скрипт никуда ничего не отправляет.

## Что внутри архива и почему

```
manifest.json
icon.png                              ровно 256x256, иначе приёмка откажет
README.md                             это package.md, страница мода на сайте
BepInEx/plugins/AstvardServerMod.dll
```

**Имя папки решает, куда менеджер положит файл** — отсюда `BepInEx/plugins`.

**Jotunn.dll внутрь не кладём.** Он объявлен зависимостью
(`ValheimModding-Jotunn-2.30.1`), а свой экземпляр рядом с менеджерским дал бы
две разные копии библиотеки. BepInEx указывать не нужно вовсе: Jötunn сам от него
зависит, и менеджер тянет всю цепочку.

**Jötunn обязателен**, а не желателен: в `Plugin.cs` стоит
`[BepInDependency(Jotunn.Main.ModGuid)]`, и без него BepInEx наш мод молча не
загрузит. На нём же держится вся панель (`GUIManager`), подсветка зон
(`MinimapManager`) и консольные команды.

## Версия

Живёт в одном месте — `internal const string Version` в `Plugin.cs`; атрибут
`[BepInPlugin]` читает её оттуда. `manifest.json` обязан повторять то же число, и
`build.py` откажется собирать пакет, если они разошлись или если в собранной DLL
этой версии нет (то есть Release не пересобран).

Правило простое:

- **минорная и патч** — всё, с чем старый и новый могут ужиться: кнопки,
  настройки, исправления. Обновляться никто не обязан;
- **мажорная** — сломанный формат обмена между клиентом и сервером. Так было с
  девятым полем строки шаблона (содержимое сундуков): старый клиент пропускает
  его молча, и сундук из постройки исчезает.

**Проверок, которые кого-то не пускают, нет намеренно.** Атрибута
`NetworkCompatibility` в моде нет: на сервер заходят и без мода, и со старой
версией. Единственное, что происходит при расхождении, — сервер сообщает свою
версию в ответ на обычный запрос панели, и клиент один раз за подключение пишет
строку в чат (`OnServerVersion` в `Plugin.cs`). Игрок, который панель не
открывает, не услышит и этого.

## Версии на сайте неизменяемы

Опубликованную версию нельзя перезалить или отредактировать — даже ради опечатки
в описании. Любая правка — это новая версия. Поле `name` менять нельзя: с другим
именем пакет зальётся как новый мод, а не как обновление старого.

## Новая версия заново проходит модерацию — и может её не пройти

**19.09.2026 заливка 1.2.1 увела весь пакет в отказ.** До неё листинг в Valheim был
`review_status: approved`, сразу после — `rejected`, на странице мода красная плашка
«Package rejected / Invalid submission», и в поиске сообщества мод перестал находиться
совсем («No results» по слову Astvard). При этом сама версия залилась: она стоит в
списке версий, значится как `Latest version`, а прямая ссылка
`/package/download/Astvard/AstvardServerMod/1.2.1/` отдаёт архив и анонимному.

Форма была заполнена как у 1.1.0: команда `Astvard`, сообщество Valheim, категории
`Mods` и `AI Generated`, NSFW выключен (категории сверены с ответом
`api/experimental/package/Astvard/AstvardServerMod/` до заливки, а не по памяти).
**Причина отказа неизвестна** — Thunderstore называет её одной строкой «Invalid
submission» и отправляет к модераторам в свой Discord. Проверять и оспаривать это может
только владелец аккаунта.

Отсюда правило: **релиз на GitHub — не дубль Thunderstore, а запасной путь**, и
выкладывать надо туда в первую очередь. Пока модерация молчит, игроки берут мод оттуда.

## Иконка

`icon.html` — исходник, снимается headless-браузером так же, как картинка превью
сайта (см. `tools/og-image/README.md`). Из корня репозитория:

```powershell
$root = "C:\cloudeCode\game\astvard"
$url = "file:///" + (($root + "\tools\thunderstore\icon.html") -replace '\\','/')
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu `
  --hide-scrollbars --force-device-scale-factor=1 --virtual-time-budget=5000 `
  --screenshot="$root\tools\thunderstore\icon.png" --window-size=256,256 $url
```

Пути абсолютные, а в URL прямые слэши — не для красоты. С относительным
`--screenshot` и с `file:///$PWD/...`, где `$PWD` подставляет обратные слэши,
Chrome выходит с кодом 0 и файл молча не создаёт. Проверено 16.09.2026, на этом
первая попытка и сорвалась.

`--headless=new` обязателен: со старым флагом Chrome выходит с кодом 0 и молча не
создаёт файл. Знак берётся из `client/img/astvard-mark.svg` — тот же, что в шапке
сайта.
