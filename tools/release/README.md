# Архив мода для релизов GitHub

Отсюда собирается архив, который выкладывается в
[релизы](https://github.com/official-fedorenko/astvard/releases). Игрок
скачивает его и распаковывает в папку с игрой — никакого менеджера модов не
нужно.

## Собрать

```bash
dotnet build valheim-mod/AstvardServerMod/AstvardServerMod.csproj -c Release
python tools/release/build.py
```

Рядом появится `Astvard-<версия>.zip`. Выложить:

```bash
gh release create v<версия> tools/release/Astvard-<версия>.zip --draft --title "..." --notes "..."
```

Черновик, а не сразу публикация: страница релиза публичная, её стоит прочитать
глазами перед тем, как она такой станет.

## Чем отличается от пакета Thunderstore

| | GitHub | Thunderstore |
|---|---|---|
| Jotunn.dll | внутри архива | зависимость, менеджер ставит сам |
| BepInEx | ставит игрок, ссылка в README | зависимость Jötunn, ставится сам |
| Обновление | скачать новый архив | кнопка в менеджере |

**Jotunn кладём внутрь намеренно.** Тут никто не разрешает зависимости за
игрока, а без Jötunn мод не запустится вовсе. Библиотека под лицензией MIT,
которая разрешает распространение при условии, что рядом лежит текст лицензии —
он и лежит, файлом `JOTUNN-LICENSE.txt`, и назван в README архива. Обновится
Jötunn — обновить и копию: берётся она из папки клиента.

**Адрес сервера в README архива не пишем.** Там ссылка на astvard.online: IP
может смениться, а страница нет. И публиковать адрес игрового сервера в открытом
релизе незачем — кто надо, дойдёт через сайт.

## Что проверяет сборщик

- версия в `Plugin.cs` и версия в собранной DLL совпадают: архив, собранный до
  пересборки Release, врал бы номером;
- дерево папок в README осталось тремя отдельными строками. Звучит мелко, но
  обратный слэш на конце строки уже дважды склеивал его в одну — сначала в
  heredoc, потом в замене; теперь это проверяется после упаковки, распаковкой.

Версия и правила версионирования — в `tools/thunderstore/README.md`, они общие
для обоих способов раздачи.
